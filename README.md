# Kepori 公开反馈站

纯静态 HTML/CSS/JavaScript，通过 GitHub Pages 发布。用户通过 Tally 表单提交，不需要 GitHub 或网站账号。

- `data/feedback.json`：只含公开反馈，由私有管理仓库自动生成。
- 不存联系邮箱、联系人哈希、兑换码、API 密钥或 Tally 原始数据。
- 本地预览：`python3 -m http.server 8765 --bind 127.0.0.1`。
- 处理状态与活动计数独立；重复反馈公开保留并关联原建议。
- 反馈数据延迟更新；`admin/` 是直连 GitHub API 的静态管理页，无后端或云函数。

## 管理

打开 [反馈管理](https://kepori-app.github.io/feedback/admin/)，首次粘贴仅授权私有 `Kepori-App/feedback-admin` 仓库 Issues 读写、Metadata 只读的细粒度 GitHub 密钥。

- **处理反馈**：点选反馈，直接点击有效、相似候选判重、分类或处理进展按钮；不再另点保存。可按需填写公开回复。
- **用户与发码**：自动按同一联系邮箱跨月累计；在待发码列表查看达标用户，手动发码后点“我已发码，标记完成”。
- **同步新反馈**：Tally 新提交经 Make 免费版立即触发既有 GitHub Actions；保留每小时检查补救，也可在管理页手动请求同步。通常几分钟公开，具体时间取决于 GitHub 排队和 Pages 部署。
- **移除恶意反馈**：详情底部「移入回收站」，同步后不公开也不计数；筛选「回收站」可恢复，不会被下次 Tally 同步重新导入。
- **导出反馈**：可按处理进展筛选；点「导出反馈」，默认下载未完成项，也可选当前筛选结果、单一进展或全部，再选分类。当前筛选导出所有匹配记录，不受每页 20 条限制。重复、无效和回收站默认排除，勾选后可纳入。
- **换设备**：已加密保存的旧设备登录后，右上角「登录与设备 → 下载加密登录文件」；在新设备登录页导入该文件，用原解锁密码登录。文件只有密文，仍需通过 GitHub 私有仓库写权限验证。
- 按钮提交后先显示同步中，私有元数据确认后才更新统计；公开页随后由 Actions / Pages 更新。
- 密钥默认仅存当前页面内存，刷新后需重新输入。可由管理员自行设置至少 10 位本机密码，以 PBKDF2（600000 次 SHA-256）+ AES-GCM 加密保存在当前浏览器；密码不上传。退出清除内存，忘记设备清除密文，不会撤销 GitHub 密钥。
- 私有数据不写入公开文件。管理页不加载第三方脚本；CSP 限制联网到 GitHub API。密码遗失可重新配置，密钥过期需去 GitHub 续建。

不要将现有 `SITE_TOKEN`、Tally 密钥或广泛权限的 CLI/OAuth 凭据输入管理页。

正式导出文件名为 `Kepori-正式管理登录.kepori-login.json`，只允许在正式 HTTPS 管理页下载。本地测试页禁止导出；曾误导出的同名联调文件在导入时会被明确识别。已有合法 v1 配置保持兼容，解锁密码不重置。手机导入失败时，先确认旧设备能解锁，再从正式页重新导出；不要从 localhost 预览取登录文件。

品牌图标来自 Kepori 现有官方资源。网站源码与 App 源码独立。

导出文件为 `Kepori-反馈-范围-时间.md`，可直接交给 AI 阅读。保留 F-ID、完整说明、分类、处理进展、有效性、时间、公开回复及已同步的公开图片／视频链接；不导出联系人字段、用户累计、发码记录、原始 Issue 或 Tally 私有下载地址。文字中的邮箱、手机号和密钥样式另行遮蔽；图片与视频内的隐私仍需自行确认。导出只在本机生成，不自动上传 AI，也不增加权限、服务器或费用。采用最后成功刷新时的快照；生成可取消，超过 10 MB 明确提示分批导出，不截断原文。

## 图片与视频

Tally 上传项选填，每条最多 3 个，单文件不超过 10MB；支持 JPG/JPEG、PNG、GIF、WebP、MP4、MOV、WebM。图片和视频会随反馈公开，用户提交前应自行遮挡隐私。视频建议 MP4，其他格式是否能直接播放取决于浏览器，始终提供原文件入口。

附件经既有 GitHub Actions 下载并验证实际文件格式，保存到 `assets/uploads/<sha256>.<extension>`，公开 JSON 只包含同站路径、类型、大小。Tally 私有下载 URL、原始文件名和上传者邮箱不发布。附件失败时保留文字反馈，后续自动重试；页面显示附件同步中。附件公开后会进入 Git 历史。

## 分类与处理进展

公开列表每页 10 条、管理列表每页 20 条，单页时隐藏分页。切换分类、关键词和进展回到第一页；关闭详情保留当前页和滚动位置。公开页默认最新提交，也可按最早提交浏览；没有编造“更新时间”。点卡片任意主体区域打开原生详情弹窗，列表只展示标题、摘要、进展和简要来源，完整内容、图片／视频、公开回复和有效性在详情查看。

管理列表点选记录后打开原生详情弹窗，处理按钮直接提交既有 GitHub 命令。关闭弹窗保留筛选、页码和未发送的回复；返回同一条反馈可继续编辑。用键盘 Tab 时保留可见焦点，用鼠标或触屏打开时关闭按钮不额外显示外框。登录文件、解锁密码、私有权限和兑换码规则保持兼容。

反馈分为问题反馈、改进建议、其他；公开列表支持点选分类、搜索和进展筛选，默认最新排序。缺少分类的历史记录显示为其他。问题显示待排查/已确认/修复中/已修复，建议显示待评估/已采纳/开发中/已完成；内部仍使用同一组稳定状态。

管理员分类与进展按钮直接提交既有命令，等待自动化确认；相似候选可直接标记重复，手动选择原反馈继续可用。分类修改不改变 ID、有效数或发码记录，查重跨分类进行。Tally 提交完成后返回 `?submitted=1` 显示同步时间提示，该参数只控制提示文字，不作为反馈入库或奖励资格依据。

布局复用官网的中性与绿色语义，原生下拉箭头保留固定留白。`interactions.css` 共享选中、焦点、按压、列表切换及原生详情动画；新输入不等待动画。系统深色模式和减少动态效果均有对应样式，公开页导航与页脚可返回官网。

移除记录不擦除既有公开 Git 历史与附件。原反馈移除时，其他重复记录保留“不计数”，暂时不显示指向已移除目标的公开链接；恢复原反馈后链接自动恢复。

## 访问次数

页脚从接入时开始累计本公开页访问次数（PV），不是独立人数，也不补填历史值。页面完整加载时请求一次，刷新会计数，分类/搜索/详情和刷新反馈列表不重复计数。开发预览及管理页不请求统计。

`visits.js` 直接请求 [soxft/busuanzi 托管 JSON API](https://github.com/soxft/busuanzi/wiki/API)，只发送固定公开地址；不引入外部脚本，不读取本机管理密文，不发送 Cookie、Authorization、查询参数、哈希、反馈正文或联系邮箱。统计服务仍会收到 IP/浏览器等网络元数据，已在折叠隐私说明中披露。服务免费开放使用，但不保证 SLA 或数据完整性；拦截/离线/超时显示“访问统计暂不可用”，不伪造数字、不自动重试递增请求，其他功能继续工作。

统计独立异步加载，最多等待 20 秒，离开页面立即取消。延长等待用于容忍慢网络，不代表服务永远可用；没有重试上报或补填计数。
